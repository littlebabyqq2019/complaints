投诉批办单管理系统（统信 UOS / 麒麟 Kylin V10）

一、要不要装 Python？
   不需要。发布包自带 Python 3.10 运行时、Tk/Tcl 界面库和全部 Python 依赖，
   全部在 _internal/ 目录里。目标机器不要装 Python，也不要 pip install 任何东西。
   只有「源码方式」（第四节）才需要系统 Python 3 + python3-tk。

二、系统只需准备这些（图形桌面本身已有 X11）：
   sudo apt install -y libreoffice-writer cups-client fonts-noto-cjk xdg-utils
   用途：
     libreoffice-writer（或 WPS）  读取旧 .doc、Word 转 PDF、打印前转换
     cups-client                    提供 lp 命令，用于打印
     fonts-noto-cjk                 中文界面与生成文档的字体
     xdg-utils                      提供 xdg-open，用于打开文档/目录
   没有打印机时 cups-client 可不装，其余功能照常。

三、运行（注意必须带 ./）
   uname -m 判断架构，选对应包解压后：
       cd 投诉批办单管理系统
       ./启动GUI.sh                ← 必须带 ./
       ./启动命令行.sh             ← 命令行批处理，也必须带 ./
   只写「启动命令行.sh」会报「未找到命令」：Linux 默认不从当前目录找命令。
   也可以：bash 启动GUI.sh

   双击「投诉批办单管理系统」若无反应，请用 ./启动GUI.sh 启动。
   启动器会自动检查：架构是否匹配、glibc 版本、缺失的动态库、图形环境，
   把错误打印出来并写入 AppData/启动诊断.log，有桌面时还会弹窗提示。

四、老系统 / 其他架构（glibc < 2.28、龙芯 LoongArch、申威等）
   源码为纯 Python，与 CPU 架构和构建机 glibc 无关。在源码目录执行：
       ./源码方式安装.sh
   或手动：
       sudo apt install -y python3 python3-tk python3-pip python3-venv \
                           fonts-noto-cjk libreoffice-writer cups-client xdg-utils
       python3 -m venv --system-site-packages .venv
       .venv/bin/python -m pip install -r requirements-linux.txt
       ./启动GUI.sh
   如需在该机器上生成原生可执行文件：
       .venv/bin/python -m pip install -r requirements-linux.txt
       .venv/bin/python -m PyInstaller complaints-linux.spec --noconfirm

五、架构对应关系
   uname -m = x86_64  → complaints-linux-x86_64.tar.gz
   uname -m = aarch64 → complaints-linux-aarch64.tar.gz
   两包不可混用。包内可执行文件与 _internal 下的 .so 是对应架构的原生机器码。

六、数据位置
   配置与数据库保存在程序目录下的 AppData/ 中，
   待打印 / 已打印 / 已处理 三个目录与程序同级，与 Windows 版一致。

七、常见故障
   先跑一次 ./诊断.sh ，它会直接打印：Tk 是否可用、ttkbootstrap 版本、
   控件自检结果、最近一次启动日志。贴出这几行就能定位问题。
   深度自检（真把界面搭一遍，不弹窗）：./投诉批办单管理系统 --selftest
   结论看 AppData/ttk_selftest.log 最后一行 RESULT。

   1) 弹窗「程序启动失败！ module 'ttkbootstrap' has no attribute 'PanedWindow'」
      原因：ttkbootstrap 2.0 起把 ttk.PanedWindow 改名为 ttk.Panedwindow，老代码
            在新版上取不到属性。本版本已由 ttk_compat.py 自动补齐别名，无需处理。
      如果仍出现（说明装的是旧程序或依赖被换成 3.x）：
      源码方式：.venv/bin/python -m pip install 'ttkbootstrap>=1.10.1,<3'
                然后 .venv/bin/python -c "import ttk_compat; print(ttk_compat.describe())"
      查看启动日志：AppData/app_startup.log（每次启动覆盖，记录依赖版本与控件校验结果）

   2) 弹窗「主题 xxx 不可用」后界面仍正常打开
      说明升级过 ttkbootstrap，旧主题名在新版里被重命名；程序会自动回退到 litera，
      在「工具 → 主题切换」里重新选一次主题即可。

   3) 源码方式报 ModuleNotFoundError: ttk_compat
      说明拿的是旧源码包。确认源码目录里有 ttk_compat.py，
      且 gui_app.py 开头是 `from ttk_compat import ttk`。

   4) PDF 能处理，Word 提示「提取数据失败」
      热线工单导出的是 Word 2003 XML 单文件（扩展名却叫 .docx），本版本已能
      自动识别文件内容并提取，不需要改文件名、不需要装 Word / LibreOffice。
      日志里出现「WordML提取成功」即表示走了正确分支。
      若仍失败，把 AppData/app_startup.log 和这个 Word 文件一并发回排查。

   5) 窗口底部按钮看不见 / 页面滚不动
      本版本已改为：二维码设置窗口可拖动调整大小、保存/取消固定在底部；
      批办单编辑页底部按钮条固定在窗口下沿，表单支持鼠标滚轮
      （麒麟 X11 用的是 Button-4/5，已一并绑定）。
      滚轮仍无效时先跑 ./诊断.sh，把 DISPLAY 与 Tk 版本一起发回。

八、WPS 与老 .doc
   系统预装的 WPS 会被自动检测并优先用于老二进制 .doc 的转换；
   Word 2003 XML 工单和标准 .docx 由程序直接解析，不需要 WPS。
   查看检测结果：./诊断.sh 里的 office / LO 两行。
   强制只走 WPS 验证：COMPLAINTS_WPS_PREFERENCE=wps ./启动GUI.sh
   只走 LibreOffice：  COMPLAINTS_WPS_PREFERENCE=off ./启动GUI.sh
   没有 WPS 也没装 LibreOffice 时，仅老 .doc 无法处理，其余格式不受影响。

九、界面显示不全 / 图标是方框
   1) 标题或编号被截掉半个字
      本版本已调整三栏默认宽度（左/中各 300px）与标题排版方式，
      标题从左起排、宽度不足只截右侧；收文编号优先占位，保证末位可见。
      如果升级后仍是老样子，请删掉 AppData/window_config.json 里的
      "paned_positions"，或在「工具」里执行一次「重置窗口布局」。
   2) 按钮前面的图标显示成方框
      系统没有可被 Tk 使用的 emoji 字体，程序会自动去掉图标只留文字。
      想让图标显示：安装轮廓版 emoji 字体（如 fonts-symbola）后
         COMPLAINTS_EMOJI=on ./启动GUI.sh
      想强制去掉：COMPLAINTS_EMOJI=off ./启动GUI.sh
      启动日志里有 emoji=... 一行说明当前判定。

十、打印报错
   1) /bin/lp：不支持的 document-format ...wordprocessingml...
      原因：Word 没能转成 PDF，程序把 .docx 直接交给了打印系统。
            本版本已改为「转不出来就报错中止」，不会再出现这条。
      解决：安装 LibreOffice（它才有命令行转换能力）
         sudo apt install -y libreoffice-writer
      装完 ./诊断.sh 里 LO 那行应显示 soffice 路径。
      不想装也可以先用「批量转PDF」转成 PDF 再打印。
   2) WPS 弹「无法打开 "pdf"」
      原因：旧版本给 WPS 传了它不支持的转换参数（WPS 无命令行转 PDF 能力）。
            本版本已移除，且只探测一次，不会反复弹。
      若仍出现，说明用的是旧程序，请更新到最新发布包。

十一、Word 转 PDF 后一页变两页
   原因：模板用的是 Windows 字体（仿宋_GB2312、方正小标宋简体），
         麒麟上没有，LibreOffice 换成别的字体，行高变了，最后一行被挤
         到第二页。不是转换出错，是字体替换的必然结果。
   本版本已做两件事：
     1) 自动给 fontconfig 写别名，优先用度量最接近的本地字体
     2) 转换后比对页数，不一致会提醒缺少哪些字体
   要完全一致，两种办法任选：
     1) 装上模板字体（最彻底，需自行取得这两个商业字体的授权）
        把 .ttf 放到 ~/.local/share/fonts/ 然后执行 fc-cache -fv
     2) 不转 PDF，直接打印 Word：
        「打印」菜单 → 「Word 直接打印（不转 PDF）」
        「打印」菜单 → 「在 WPS 中打开当前文件并手动打印」（版式最保真）
   也可以用环境变量改默认行为：
        COMPLAINTS_PRINT_MODE=direct ./启动GUI.sh
      可选值：pdf（默认，兼容性最好）/ direct（直接打 Word）/ word（交给 WPS）

十二、为什么不能把 Word 直接交给打印系统
   Linux 的打印队列（CUPS）只认 PDF、PostScript、图片这类「打印就绪」格式，
   不认识 .docx。直接递过去就会报「不支持的 document-format」。
   Windows 上之所以能直接打印 Word，是 Word 程序自己排版后送给打印机，
   真正干活的是 Word 而不是打印系统。Linux 上扮演这个角色的是
   LibreOffice / WPS，所以必须先由它转成 PDF，或由它自己调打印。

十三、打印报「symbol lookup error / undefined symbol: FT_Done_MM_Var」
   这不是 LibreOffice 坏了，也不是缺字体，而是「库版本冲突」：
   打包版程序启动时会把自己目录下的库路径加到 LD_LIBRARY_PATH，
   而我们目录里带着旧版 libfreetype，于是 LibreOffice 启动时加载到了
   旧库，系统需要的 FT_Done_MM_Var 符号找不到，直接报错退出。

   所以：重装 LibreOffice 没用（它本身是好的），装字体也没用。

   本版本已从两层修好：
     1) 打包时不再把 libfreetype / libfontconfig / libcairo 等
        系统自带的基础库打进程序目录
     2) 每次调用外部程序（LibreOffice、WPS、打印命令、字体命令）时，
        自动清掉程序自己的库路径，让它们用系统自己的库

   升级到最新发布包即可，不需要做任何配置。

   若想确认旧包状态，可运行（只读，不改系统）：
       bash 修复打印.sh
   它会显示系统 freetype 有没有该符号、实际加载的是哪个库、
   程序目录里是否还有冲突库，并给出处置建议。

   在修好之前也能打印：用 WPS 打开批办单，点 WPS 的打印按钮，
   或程序中「打印」菜单 -> 「在 WPS 中打开当前文件并手动打印」。
